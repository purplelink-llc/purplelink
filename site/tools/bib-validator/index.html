How to validate a BibTeX file online

  1. Upload your .bib file (drag-and-drop or click), or switch to Paste text and drop the BibTeX directly. Up to 2 MB.
  2. The CrossRef existence check is on by default, and syntax, required-field and duplicate-key checks always run. Tick DOI resolution or Semantic Scholar to add them, or untick CrossRef to skip outside lookups.
  3. Click Validate .bib. A color-coded table shows each entry. Click any row to see the original BibTeX, plus the corrected version when CrossRef returned a confident match. Use the filter chips to focus on warnings or errors.
  4. Download the annotated .bib (your file with status comments) or the corrected .bib (entries rewritten from CrossRef metadata where confidence is high).

If the table lists errors you do not recognize, read how to fix the errors the validator finds. The guide gives a before and after for each of the eight most common.

See it catch real faults

This is a small .bib file with common faults added on purpose. The output below is what the validator's own code returned for it, with only the always-on checks (syntax, required fields and duplicate keys) enabled.

Input

@article{ampel2023trust,
  author  = {Ampel, Benjamin and Doe, Jane},
  title   = {Trust in automated review tools},
  journal = {Journal of Examples},
  year    = {2023},
}

@article{smith2021missing,
  author  = {Smith, Alex},
  title   = {A study with no journal},
  year    = {2021},
}

@inproceedings{lee2022noyear,
  author    = {Lee, Sam},
  title     = {A conference paper with no year},
  booktitle = {Proceedings of the Example Conference},
}

@book{ng2020book,
  author = {Ng, Priya},
  title  = {A book with no publisher},
  year   = {2020},
}

@article{ampel2023trust,
  author  = {Ampel, Benjamin},
  title   = {A second paper that reuses the first key},
  journal = {Journal of Examples},
  year    = {2024},
}

@article{brown2019brace,
  author  = {Brown, Kim},
  title   = {An entry with an unclosed brace,
  journal = {Journal of Examples},
  year    = {2019},
}

Output

Summary: 1 OK, 0 warnings, 4 errors, 5 entries total. The annotated .bib puts one comment line above each entry:

% [bib-validator] OK | fields OK
% [bib-validator] ERROR | MISSING: journal
% [bib-validator] ERROR | MISSING: year
% [bib-validator] ERROR | MISSING: publisher
% [bib-validator] ERROR | fields OK | DUPLICATE KEY: ampel2023trust is already used at line 1

The last entry is the one that reuses ampel2023trust. Only the second use is flagged, and the message names the line of the first. Keys are compared without regard to letter case, so Ampel2023Trust would be flagged too. BibTeX and biber treat them as the same key.

What it did not report

The file has six entries and the table lists five. The last entry, with the unclosed brace in its title, is skipped by the parser and gets no message. Check that one by hand, or with your LaTeX build log. The guide on how to fix common BibTeX errors covers it. If your entries are missing fields because they were typed by hand, build BibTeX from DOIs instead.

About this tool

This tool validates BibTeX files in layers: syntax, completeness and duplicate keys (always, with no external calls), DOI resolution (opt-in), an existence check against CrossRef (on by default) and Semantic Scholar (opt-in). When you enable the database checks, it also compares authors and publication years and can produce a corrected .bib for high-confidence matches. This catches AI-hallucinated citations, which have plausible-looking metadata but do not correspond to real papers.

Can it detect AI-hallucinated citations?
Yes. The CrossRef check is on by default, and Semantic Scholar can be added. For each entry with a title, the tool queries the database. It reports how closely the title and author list match a real paper and whether the year is off. Low-confidence title matches (below 50%) and author mismatches on otherwise-confident matches are flagged as likely hallucinations. For the full workflow and how the detection methods compare, see the guide on catching AI-hallucinated citations.
Are my files stored?
No. Your .bib file is read on our server for the check and not kept. When the CrossRef, DOI or Semantic Scholar checks run, titles and authors are sent to those external services. This is disclosed before you run the check.
How does the duplicate-key check work?
It compares the citation keys of all entries in the file, ignoring letter case, because BibTeX does. Every entry after the first that reuses a key is marked as an error, and the message gives the line of the first use. @string, @preamble and @comment blocks are not entries and are ignored. Separately, an entry with a different key but the same DOI, or the same title, as an earlier entry gets a "possible duplicate" note. That note does not change the entry's status, because the same paper can legitimately appear twice.
What does the annotated .bib contain?
Your original .bib file with a comment line above each entry. The comment shows the validation status: missing required fields, duplicate keys, DOI result, title and author confidence scores, and any year mismatch. Paste it straight back into your editor.
What is the corrected .bib?
The corrected .bib covers each entry where CrossRef returned a high-confidence match (title similarity at least 85%). It replaces the entry's fields with CrossRef metadata: title, author list, year, DOI, journal or booktitle, volume, issue, pages, and publisher. Entries without a confident match are passed through unchanged. Each rewritten entry is marked with a "CORRECTED from CrossRef" comment so you can audit the changes.
How does the author check work?
Names are normalized to canonical last-name tokens (folding "John Smith", "Smith, John", "J. Smith", and "Müller" → "muller" all to the same key) and compared as a set against the authoritative author list. The score is the Jaccard overlap, so partial matches still get partial credit.
What BibTeX entry types are supported?
article, book, inproceedings, proceedings, phdthesis, mastersthesis, techreport, misc, incollection, inbook, booklet, manual, conference, unpublished, and thesis.
