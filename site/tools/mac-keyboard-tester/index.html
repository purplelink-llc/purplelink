What a web page cannot see

  • The fn (Globe) key is never reported to a web page. It is drawn with a dashed border for that reason.
  • Brightness, volume, media, Spotlight, Dictation and Touch ID keys are handled by macOS first, so the browser does not see them. On most Macs the top row sends those actions unless you hold fn.
  • If a key does not light, the browser did not see it. That does not mean the key is broken. Open Keyboard Viewer from the Input menu (turn the menu on in System Settings, Keyboard) to check keys the page cannot.
  • macOS sends no key-up for a key pressed while Command is held, so the held count clears when you release Command.

About this tool

Does the keyboard tester record what I type?
No. The page reads which physical key was pressed, as a key code such as KeyA, and lights that key. It does not read characters, and nothing you press is stored, logged or sent anywhere.
Why does a key not light up?
The browser did not see it. That does not mean the key is broken. The fn (Globe) key, brightness, volume, media and Touch ID keys are handled by macOS before a web page can see them. Check those in Keyboard Viewer, which you can open from the Input menu once it is turned on in System Settings under Keyboard.
Why do F1 to F12 not light up?
On a Mac, the top row usually triggers brightness, volume and media actions instead of sending F1 to F12. Hold fn while you press a key, or turn on Use F1, F2, etc. keys as standard function keys in System Settings under Keyboard, Keyboard Shortcuts, Function Keys.
Where do the sounds come from?
They are the recordings that ship in Keyfeel, our Mac app, released under CC0 1.0 and credited on the Keyfeel sound credits page. The files are served from this site, and sound stays off until you turn it on.
