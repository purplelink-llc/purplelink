Xcode and the iOS simulators: where the space goes and how to get it back

By Benjamin Ampel · November 9, 2026

Most of the space Xcode takes sits in five places: simulator runtimes, simulator devices, DerivedData, iOS DeviceSupport and Archives. Xcode rebuilds most of it. Archives it cannot. This guide says what each folder holds, what is safe to remove, and which commands Apple provides.

Disclosure up front: Purplelink, which publishes this site, makes one app mentioned near the end, Legroom, a menu-bar app sold as a 7-day trial and a $9.99 one-time purchase. I took the sizes and command output below from my own Mac on November 9, 2026 (macOS 27.0.1, Xcode 26.3, build 17C529). Every command I ran was read-only. I did not run any delete command. For those, I read the syntax from the help that ships with this Xcode. Sizes are from one Mac and yours will differ.

The short answer

Xcode keeps the simulators' operating systems (runtimes), the simulators themselves, its build output and the symbol files for devices you have plugged in. They add up quickly. The folders Xcode regenerates are safe to clear once you quit Xcode. Your shipped builds in Archives are not, because you may need them to read crash reports later. For the runtimes, which are the largest items, use Xcode or xcrun simctl runtime delete, not Finder.

What each folder holds

Sizes in the last column are what du -sh reported on my Mac. It had 14 iOS and 5 watchOS simulators and had never archived or connected a device for debugging, so two folders do not exist there.

The sources agree on the broad picture. MacPaw's article (last updated September 21, 2026) lists DerivedData, CoreSimulator, DeviceSupport and Archives, and advises keeping archives for builds that are live or in review and making sure crash-report symbols are uploaded before deleting any. Donny Wals (2020) covers DeviceSupport and notes that macOS may clear Device Support files unused for 180 days. StorageRadar's page (updated August 31, 2026) is on the same topic. StorageRadar sells a disk-cleaning app, so it is a competitor of Legroom. Those pages give their own size figures. I do not repeat them, because sizes depend heavily on how many runtimes and simulators you keep.

Measure first

These commands only read. du may print permission errors for protected folders, and the ones named below were readable on my Mac.

du -sh ~/Library/Developer/Xcode/DerivedData
du -sh ~/Library/Developer/CoreSimulator/Devices
xcrun simctl runtime list
xcrun simctl list devices

On my Mac, xcrun simctl runtime list printed iOS 26.3.1 (23D8133) and watchOS 26.2 (23S303), both Ready, and ended with "Total Disk Images: 2 (11.4G)". If Xcode is not in your Applications folder, as on my Mac, xcrun needs to know where it is. Set it with xcode-select or the DEVELOPER_DIR variable.

Where the runtimes are

With recent Xcode, macOS stores the runtimes itself. On my Mac, /System/Library/AssetsV2/com_apple_MobileAsset_iOSSimulatorRuntime measured 7.8 GB and the watchOS folder next to it 3.6 GB. Those two add up to the 11.4 GB that simctl reported. That is a protected system folder. Remove runtimes with Xcode or simctl, never by hand. StorageRadar gives the same advice and adds that runtimes are shared by every user account on the Mac.

In Xcode, open Settings and look for the Components pane, which lists the installed runtimes and lets you delete them. I did not open it for this guide. The forum thread cited below shows a person using it in Xcode 26.2.

Apple's commands

I read these from xcrun simctl help delete and xcrun simctl runtime help on Xcode 26.3. I did not run them. Run the list commands first so you know what each one will touch.

Remove simulators

xcrun simctl delete unavailable

The help says this deletes simulators that the current Xcode SDK does not support. That is the safest of the delete forms, because those simulators can no longer run. The same help also lists xcrun simctl delete <device> for named simulators and xcrun simctl delete all for every simulator. Deleting a simulator removes the apps and data inside it. A related command, xcrun simctl erase, resets a simulator's contents and settings and keeps the simulator.

Remove runtimes

The runtime help lists this form:

xcrun simctl runtime delete (<identifier>|--notUsedSinceDays <days>) [--dry-run]

The identifier is the UUID that xcrun simctl runtime list prints beside each runtime. The help says --notUsedSinceDays deletes images not used within that many days, and that --dry-run prints what would be deleted without deleting anything. Use --dry-run first. The help also describes an alias, all, that removes every runtime, and it says any booted simulators on a runtime are shut down first. A deleted runtime is downloaded again in Xcode, which is a large download.

When a runtime stays after you delete it

This is one forum report, not Apple's guidance. In an Apple Developer Forums thread started in January 2026, a developer on Xcode 26.2 described an iOS 18.5 runtime of about 9 GB left in the AssetsV2 folder. They said Xcode's settings did not list it, simctl runtime delete reported no runtime found, and removing it by hand was refused because the folder is protected. Other users in the thread reported the same. An accepted answer said the problem was fixed in a later Xcode beta, where deleting in the settings removed the leftovers. It also said the savings showed only after a Time Machine backup ran. An Apple engineer there said that turning off SIP, the system protection, to remove the folder is not supported.

I did not see this on my Mac, and I do not suggest touching the protected folder. If a runtime does not show in Xcode but still takes space, update Xcode and try Xcode's own removal again, or ask on the forums.

Where Legroom fits

Legroom is the app I make. It measures simulator runtimes and CoreSimulator data, so you can see their sizes before you act. It also has a rule that removes simulator runtimes you have not used for a set time. The default is a week, and the rule runs Xcode's own xcrun simctl runtime delete command. The rule also removes the simulators that depend on that runtime. Legroom does not delete anything under /System by hand. Frequently asked

Is it safe to delete DerivedData?

Yes, in the sense that Xcode builds it again. MacPaw describes it as build products, indexes and caches, and says the next build is slower. Quit Xcode first and delete the folders inside DerivedData, then build as usual.

Will deleting a simulator delete my app's code?

No. Your source code lives in your project folder. A simulator holds an installed copy of the app and the data it saved there, such as its database and settings. Deleting the simulator removes those, and the next run installs the app again.

How do I see what is installed before I delete anything?

Run xcrun simctl runtime list for the runtimes and xcrun simctl list devices for the simulators. Both only read. The first ends with a total, which on one Mac with Xcode 26.3 was 2 disk images and 11.4 GB.

Can I delete the folder in /System/Library/AssetsV2 by hand?

No. On recent Xcode, macOS stores the runtimes there and the folder is protected. Remove runtimes with Xcode or xcrun simctl runtime delete. A forum report describes one runtime that stayed behind after deletion, and Apple's engineer there said turning off SIP to remove it is not supported.

Why is System Data still large after cleaning?

Several things count toward it that are not Xcode, and free space can lag. One forum poster said the savings appeared only after a Time Machine backup ran. The guide on why System Data is so big on a Mac lists the other usual causes.
