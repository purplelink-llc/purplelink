Buddy

A small companion for Claude Code that lives in your MacBook notch. It shows what each Claude Code session is doing, and it opens when a session needs you.

Download for Mac Source on GitHub

Version 0.10.1. A ZIP file from the latest GitHub release. Open it and move Buddy to Applications. The app is notarized (checked by Apple).

Needs a Mac with Apple silicon, macOS 14 or later, and Claude Code. MIT license. Made by Purplelink LLC.

What it does

  • Working. A little character sits beside the notch and glances around while Claude works. A blue dot, with a count, shows how many sessions are busy.
  • Needs you. When a session asks for permission, asks a question, or has a plan for you to review, Buddy hops, plays a sound, and opens for 20 seconds. After that an orange badge stays until you answer.
  • Finished. Buddy smiles, plays a chime, and says how long the turn took, such as "Finished in 3m 12s". A green check stays until you hover over the notch.
  • Jump to it. Click a session to open that exact chat in the Claude app, that exact Terminal or iTerm2 tab, or that project's VS Code or Cursor window. Click or swipe a row to clear it.
  • Session usage. Beside the character, Buddy always shows how much of your 5-hour session window you have used and when it resets, for example "≈64%" over "2:20". It turns orange at 70% and red at 90%. Just right of the notch, a countdown shows how long until the session resets. The number is estimated from the token counts in your chats on this Mac, which is what the "≈" means. Turn on Exact usage from Anthropic in Settings for exact session and weekly numbers; if Claude Code isn't signed in, Sign In… in Settings starts the sign-in. The top of the open list adds a usage meter.
  • Usage limits. When a limit pauses your chats, Buddy counts down to the reset and lists the paused chats, including ones paused before Buddy was running. Continue now types "continue" into each of them, and Auto does it for you about a minute after each chat's own limit resets. If a chat is still paused, Auto tries again, up to three times. Buddy can't type into a locked Mac, so it tries again the moment you unlock, and an opt-in setting keeps the Mac from locking on its own while chats wait. To type, Buddy brings the Claude app forward for a few seconds and types only into that chat's own message box, then puts you back where you were. It leaves alone any chat with unsent text in its message box.
  • Dropped connections. When a chat stops because the network dropped or the Mac went to sleep, Buddy retries it on its own once you are back online. It presses the chat's Try again button, or types "continue", at most three times.
  • Settings. Right-click Buddy, then Settings…, to choose sounds (for chats that need you and for finished ones, separately), Auto, connection retries and open at login, see whether Accessibility is allowed, and turn automatic updates on or off.
  • Automatic updates. Buddy checks for a new version once a day and installs signed, notarized updates through Sparkle. Check for Updates… in Settings checks right away, and Check for updates automatically turns the daily check off.

Buddy has no Dock icon and no account. Until it knows your usage, it hides completely when nothing is happening.

What Buddy can access

Buddy asks for more than most small apps, so here is all of it.

  • Your Claude Code events. Claude Code runs buddy-hook at each step of a session: a prompt, a tool call, a question, a finish. The hook writes the event to a folder that exists only while Buddy is running. It adds about 4 to 5 ms per event on an M-series Mac. When Buddy is closed, the hook does nothing.
  • The ends of your session transcripts. Buddy reads the last 64 KB of a transcript in two cases: to notice that you pressed Esc, since Claude Code sends no event for that, and to find chats a usage limit paused. Buddy never sends them anywhere.
  • The Claude app's chat list. Buddy reads the first 16 KB of each chat file in ~/Library/Application Support/Claude. It uses them to show chat titles instead of folder names and to find paused chats.
  • Accessibility, if you allow it. Buddy uses it only to type "continue" into paused Claude app chats, or to press Try again in a chat a dropped connection stopped. It waits until the screen is unlocked, and for Auto until you stop typing, then puts you back in the app you were using.
  • Automation, if you allow it. macOS asks once before Buddy brings a Terminal or iTerm2 tab forward or sends "continue" to it.
  • A small log. Buddy keeps a log of what it does, chat titles included, in ~/Library/Logs/Buddy/buddy.log, capped at about 1 MB.
  • Token counts in your transcripts. For the usage number, Buddy adds up the tokens your chats on this Mac used in the current 5-hour window and compares that with what your recent session limits took. It shows the result with "≈".
  • Your Claude Code sign-in, if you turn it on. Exact usage from Anthropic is off by default. If you turn it on in Settings, Buddy reads Claude Code's sign-in from your keychain with /usr/bin/security, the same tool Claude Code stores it with, so there is no password prompt. When the sign-in has expired, Buddy runs claude doctor to renew it. It then asks Anthropic's usage service every few minutes for your exact session and weekly usage. The sign-in is used only for that request and is never stored or logged. Settings shows which account it is and can switch accounts or sign out.

Buddy uses the network for two things only: the daily update check, which fetches appcast.xml from the purplelink-llc/buddy repository on GitHub and the update itself from GitHub Releases, and exact usage if you turn it on. Both can be turned off in Settings. Everything else stays on your Mac.

Requirements and setup

  • A Mac with Apple silicon.
  • macOS 14 or later.
  • Claude Code, either the claude command or the Code tab of the Claude app.

Open Buddy and click Connect in the banner it shows in the notch. Buddy adds its hook to ~/.claude/settings.json, keeps a backup next to it, and copies a small program to ~/.claude/hooks/buddy-hook. Sessions that start after you connect appear in Buddy. To remove it, right-click Buddy, choose Settings…, and click Disconnect next to Hook. That removes its hook entries and ~/.claude/hooks/buddy-hook, and leaves your other hooks alone. Then quit Buddy and delete it from Applications.

Known limits

Claude Code's hook events are documented. Three Buddy features depend on parts of the Claude app that Anthropic does not document, so an app update can break them without notice:

  • Chat titles and paused-chat detection, which read the Claude app's chat files.
  • Jumping to a chat in the Claude app, which uses the app's claude://code/continue link.
  • Continue now and Auto, which type into the app's message box.

When one of these breaks, Buddy falls back to the folder name, to bringing the app forward, or to doing nothing. If that happens, please open an issue on GitHub.
