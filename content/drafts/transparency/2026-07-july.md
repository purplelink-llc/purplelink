# Purplelink — July 2026 Transparency Report

## What Shipped

**Kits in the primary navigation.** Kits — the code product store with the Clip Pipeline, Faceless Content Pipeline, and Monetization Stack — was reachable only from the footer. Footer links get almost no clicks. On July 26 I moved Kits into the top nav on every page that carries one, positioned third after Software and Products. I verified it at 375px mobile width before committing. The digest page templates were updated at the same time so tomorrow's digest didn't immediately break the new nav. ([a59ce22](https://github.com/purplelink-llc/purplelink/commit/a59ce22))

**Client-side tool tracking.** Seven of Purplelink's tools call a backend service; those runs were already counted. Two weren't: the citation generator and the LaTeX table generator both compute entirely in the browser with no network call. From the stats dashboard's perspective, they looked like page views. The fix was deciding what counts as a run for each — which turned out to be different for each tool. For the citation generator, a run means a form submission or DOI lookup: a deliberate request. For the table generator, which regenerates on every keystroke, I count once per visit, the first time real output appears. ([published July 29](https://purplelink.llc/blog/what-counts-as-a-run/))

**Traffic dashboard fix.** A bug in the internal traffic dashboard described a counter as starting "today" when it actually started yesterday. The age was derived from the count of complete days rather than the actual start date. Fixed with a one-line change in the same commit as the nav update.

## What We Decided (and Why)

**Put Kits in the nav, even though it meant touching 149 files.** The alternative was leaving Kits in the footer and watching it get zero organic traffic. The nav change required updating every existing page and every digest template — a large, mechanical diff. I verified the diff was only the nav line on the digest files before committing and used a commit flag (`ALLOW_DIGEST_COMMIT`) to mark the intentionality. The decision was simple; the execution took care.

**Count differently for different client-side tools.** I could have used a single rule — first interaction, or any interaction, or per-page-visit — and applied it uniformly. I didn't, because the tools work differently. The citation generator produces discrete outputs (you ask, it answers). The table generator is iterative (you type, it updates continuously). Using the same metric for both would have made one of them meaningless. This took longer to think through than the code took to write.

**Skip building the word counter tracking for now.** The word counter and a handful of other client-side tools still don't have run tracking. I wrote about the ambiguity publicly — when do you count a run for a word counter? When you paste text? When you copy the output? I haven't settled on a definition I believe in. Adding a number I don't trust would be worse than having no number. I left it as a placeholder in the dashboard.

## What Didn't Work

**Paid checkout is still off.** Paper Review, Citation Gap, Cover Letter, Anonymity Check, and Response Review all have real backend infrastructure. The checkout buttons are set to "Coming soon." Stripe is not yet activated. This has been the state since these tools launched. The runbook (`docs/paper-review-runbook.md`) exists and is current. The delay is mine: setting up Stripe and testing the payment flow is a few focused hours of work that I have not done. I keep deprioritizing it in favor of content, which does not generate revenue.

**The Clip Pipeline kit pre-ship audit found seven problems.** One file hardcoded two real Facebook Page IDs from my internal setup. A file the publisher depended on was missing entirely — it would have been unusable on a fresh install. A machine-specific path to my yt-dlp installation was hardcoded. iCloud sync wrote into the buyer's iCloud Drive on every run without prompting. Filenames derived from user-supplied YouTube URLs weren't sanitized. The product copy claimed a longform compiler that stitches clips into a single video; that module no longer existed in the code. All of these were fixed before the kit went live, but the fact that they were there at all reflects how different internal tooling and sold code are as obligations. I built it for myself and hadn't read it as a buyer.

**No content published in the first half of July that wasn't already drafted.** The weekly cadence was maintained, but looking at the draft dates, all five blog posts and all five guides for July were drafted the week they published. There's no buffer. When one week is harder, the cadence breaks.

## What We Learned

**The pre-ship audit for the Clip Pipeline was the most useful thing I did all month.** Reading my own code as a stranger — someone who just paid for a zip file and is trying to run it — surfaced things I would never have caught from the inside. The missing publisher dependency was in there for who knows how long. The lesson isn't "audit more carefully" in the abstract; it's that the mental model shifts when you're holding someone else's money. That shift needs to be recreated deliberately.

**Attention degrades across long context windows in ways that don't show up as errors.** I wrote about this in the Daily Digest post, but it landed harder in practice than I expected. Sending 700-plus raw candidates to the curation model in a single call produced picks that were measurably less sharp at the bottom of the list. The model wasn't failing — it was still selecting plausibly relevant items. But the selections from item 600 weren't as good as the ones from item 60. The pre-filter (capping at 18 per source category before the final call) fixed this, and the quality difference was visible to me without a formal evaluation. I had assumed context length was the constraint. It wasn't.

**Footer links are effectively invisible.** This isn't surprising in the abstract, but seeing Kits traffic before and after the nav change makes it concrete. The store existed. The products existed. The footer link existed. Almost nobody found it. Distribution and product are both real things and they require the same level of deliberate attention.

## What's Next

**Activate Stripe and enable paid checkout on at least one tool.** Done means: Paper Review is purchasable in production, the Stripe webhook is live, and a real payment has been processed end-to-end. Not "set up a test account." A real transaction. The checkout flow, error handling, and receipt email all need to work before I call this done.

**Build a content buffer.** Done means: at least two weeks of drafted blog posts and guides exist in `content/drafts/` that are ready to publish without additional editing. Right now everything publishes the week it's written. One difficult week would break the cadence entirely.

**Define and implement tracking for the remaining untracked client-side tools.** Done means: the word counter, and any other tool that computes in-browser without a backend call, fires a usage event, and those events appear correctly in the stats dashboard. This requires settling the definitional question I've been avoiding, not just writing the code.
