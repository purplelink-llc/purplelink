How it works

It hears that a key was pressed

Through the macOS Input Monitoring permission, Keyfeel is told when a key goes down and comes back up. It uses the key code, which says which key it was, and never the characters you typed.

It plays a recording of a real switch

Each press plays a recording from the sound profile you chose, and picks a different recording each time, so a repeated key does not sound like one sample on a loop.

It stays out of the way

Keyfeel lives in the menu bar. You can silence it in the apps you choose, and it goes quiet by itself while the microphone is in use.

What it does

Sound profilesRecorded Tactile, Cherry MX Brown and Dome profiles, plus synthesized extras. You can also import your own sound.
KeysPress and release sounds, with a different recording on each press. Each key has its own pitch, and the sound moves from left to right in stereo across the keyboard. The space bar and Return have sounds of their own.
MousePress and release sounds for mouse clicks, and a ripple on screen where you click.
ScrollingScroll ticks that follow how fast you scroll.
TrackpadOptional haptic feedback on scroll and click. Keyfeel produces it only while a finger is on the trackpad.
QuietSilence in the apps you choose, and automatic silence while the microphone is in use.
ControlKeyfeel runs from the menu bar and is controlled there.

Privacy

Works offline

Keyfeel makes its sounds and haptics on your Mac and needs no network connection. There are no accounts. The only network use is the paid app's check for a new version and, for buyers, the download.

Key codes, never characters

To choose a sound, Keyfeel needs to know which key was pressed. It reads the key code, not the character the key produced. A key code is still a record of which keys you press, which is why macOS puts it behind a permission you grant.

Password fields stay silent

When a password field has focus, macOS stops delivering keystrokes to apps like Keyfeel. It hears nothing while you type a password.

Details are on the privacy page.

The Input Monitoring permission

The first time you open Keyfeel, macOS asks you to allow it under System Settings, Privacy & Security, Input Monitoring. That is the permission an app needs to be told about key presses made in other apps. Without it Keyfeel cannot hear your keyboard and stays silent. You can switch it off again in the same place at any time.

What it is not

A keyloggerIt works from key codes, not the characters you type, and it does not send your typing anywhere.
A keyboard remapperIt listens. It does not change what a key types and does not block any key.
New hardwareSounds play through your Mac's audio output. Haptic feedback is felt only on the trackpad, and only while a finger is on it. Nothing happens inside your keyboard or mouse.
Cross-platformMac only. There is no Windows, iPhone or iPad version.

Frequently asked questions

What does it need to run?
macOS 13 (Ventura) or later, on Apple silicon or Intel, and the macOS Input Monitoring permission.
Does it read what I type?
No. It reads which key was pressed, as a key code, so it can choose a sound. It does not read the characters. It works offline and does not send your typing anywhere.
Does it hear me type passwords?
No. When a password field has focus, macOS stops delivering keystrokes to apps like Keyfeel, so it hears nothing there.
Can I make it quiet in some apps, or on calls?
Yes. You can silence Keyfeel in the apps you choose, and it goes quiet by itself while the microphone is in use.
Why do the haptics need a finger on the trackpad?
Keyfeel produces trackpad haptics only while a finger is on the trackpad, which is when you can feel them. They are optional.
