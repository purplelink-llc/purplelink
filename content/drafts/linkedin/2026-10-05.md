## Option 1

Every click on my homepage was going to GlobePin for a few hours last week.

I use a stretched-link pattern on the product cards: each card is one anchor tag, and a pseudo-element with position absolute and inset zero expands to cover the whole card, so a visitor can click anywhere on it, not just the title text. It is a clean pattern and I use it elsewhere on the site without trouble.

The problem was one missing line. The anchor itself had no position relative set on it. Without that, the browser will not stop the absolutely positioned pseudo-element at the edges of its own anchor. It keeps climbing the document until it finds a positioned ancestor, or runs out and covers the whole page. GlobePin happened to be the first product listed, so its invisible, page-covering click target sat on top of every other card, every other link, everything below it.

The fix was one CSS declaration: position relative on the anchor. I found the cause by resting my cursor on three different product names and watching the status bar point to the same link each time.

Small bug, a little embarrassing once I saw what it was doing, fixed in under a minute once I found it. The homepage is back to normal at https://purplelink.llc/.

## Option 2

I spent part of last week building a tool I will probably never need myself: a Thesis Format Checker that reads a thesis or dissertation PDF and checks it against the formatting rules a graduate school actually sets.

Page size, margins against the minimums you type in, body font size, whether every font is embedded, page number sequence, line spacing, and whether the front matter headings a program requires are present. All of it runs in the browser using pdf.js, which I host myself from the vendor files rather than pulling from a CDN, so the PDF never leaves the machine it is opened on and nothing about the file touches my server.

The harder design question was not the checks. It was university rules. Every graduate school writes its own formatting guide, and I am not going to guess at a rule when I can be wrong about something that gets a thesis bounced back by a formatting reviewer. So the tool ships with a form instead of a guess: tell me your school, and I will add its rule set. Georgia State is the first one in, because it is the one I could read closely enough to get right.

It is free, at https://purplelink.llc/tools/thesis-format-checker/.

If your program has a formatting guide you would want checked against, I would like to know which one.

## Option 3

Purplelink has been dark by default since last week. Light mode still exists, as a toggle in the footer, but a new visitor now gets dark on the first paint, not whichever their operating system prefers.

The old approach used a prefers-color-scheme media query, so the site matched the visitor's system setting automatically. That sounds like the more respectful default, and for a lot of sites it is. For this one it meant the dark palette I actually designed around, the one the purple accent and the screenshots are tuned for, was only ever seen by visitors whose Mac or phone happened to already be in dark mode. Everyone else saw a theme I had spent far less time on.

So I flipped the default. Dark rules are now unconditional, written as a selector that only backs off when a visitor has explicitly chosen light, rather than living inside a system-preference block. A small script applies a saved light choice before the page paints, so there is no flash of the wrong theme on reload. The one exception is the daily digest pages, which are generated by a separate script on a cron job and already rendered dark, so I left those alone rather than touch machine-written output by hand.

It is a one-line philosophical change that touched about sixty files. The site is at https://purplelink.llc/.
